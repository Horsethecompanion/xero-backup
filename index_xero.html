How to use it

Step 1 Check Python is installed ⌄

Open Terminal (Mac/Linux) or Command Prompt (Windows) and run:

python3 --version

If it prints a version number (e.g. Python 3.9.6) you're good. If you get "command not found", download and install Python from python.org first.

Step 2 Download the four scripts ⌄

Use the download buttons above to save all four .py files into the same folder on your computer — e.g. a new folder called xero-backup on your Desktop.

💡 All four scripts need to be in the same folder. The backup script also creates its output folders there.
Step 3 Install dependencies ⌄

In Terminal, run:

pip3 install requests pyopenssl openpyxl

If pip3 isn't found, try pip instead. You only need to do this once.

Step 4 Set up a free Xero Developer app ⌄

This is the main setup step. You need to register a free "app" with Xero so the scripts can authenticate with your account.

4a. Go to developer.xero.com and sign in with your normal Xero credentials — no new account needed.

4b. Click My Apps in the top navigation, then New App. Fill in:

  • App name: anything, e.g. My Backup Script
  • Integration type: Web App
  • Company or application URL: https://localhost
  • Privacy policy and Terms URLs: leave blank

Click Create App.

4c. In the left sidebar, click Configuration. Set the Redirect URI to exactly:

https://localhost:8080/callback
⚠️ Xero requires https:// even for localhost. Don't use http://.

Click Save. Your Client ID will now appear on this page.

4d. Click Generate a secret to create your Client Secret. Copy both values — you'll need them in Step 6.

💡 If the Client ID doesn't appear immediately after saving, try refreshing the page.
Step 5 Generate a local TLS certificate ⌄

Because Xero requires https://, the login script needs a self-signed certificate for a local server. This only runs on your own machine.

In Terminal, navigate to the folder you put the scripts in, then run:

cd ~/Desktop/xero-backup
python3 1_generate_cert.py

You should see:

Created cert.pem and key.pem
⚠️ Make sure you cd into the scripts folder first. If you run the script from your home directory, cert.pem and key.pem will end up in the wrong place and Step 6 will fail.
Step 6 Log in to Xero (one-time) ⌄

Open 2_login.py in a text editor and paste in your Client ID and Client Secret from Step 4d:

CLIENT_ID = "paste your client ID here"
CLIENT_SECRET = "paste your client secret here"

Save the file, then run it:

python3 2_login.py

This will open your browser to Xero's login/consent page. Log in and click Allow Access. Your browser will redirect to https://localhost:8080/callback and show a "Success!" message.

🔒 Browser security warning: You may see "your connection is not private" or "Safari can't verify the identity". This is expected — the certificate is self-signed and only used on your machine. Click Advanced → Proceed to localhost (Chrome) or Visit Website (Safari).
⚠️ If Safari shows "can't connect to the server": the local callback server wasn't running when the browser arrived. This usually means the script errored before it started listening. Check the terminal for errors — the most common cause is cert.pem not being in the same folder as the scripts (see Step 5).

At the end, the script prints your connected Xero organisation name and saves tokens.json and tenants.json. You only need to do this once.

Step 7 Run the backup ⌄ 
python3 3_backup.py

This pulls down everything: invoices, bills, contacts, bank transactions, manual journals, payments, invoice PDFs, all attached receipts and scans, and files from the Xero Files inbox.

✅ Safe to stop and restart at any time. The script skips anything already downloaded, so it resumes where it left off. Just run python3 3_backup.py again.
⏱ A note on rate limits Xero allows 60 API calls per minute and 5,000 per day. The script handles this automatically — it paces itself, and stops with a clear message if the daily limit is hit. For a large account with years of data, expect 2–3 evening runs to complete the full backup. Just kick it off before bed and check in the morning.

Output goes into a xero_backup/ folder in the scripts directory.

Step 8 Reformat into browsable files ⌄

Once the backup has finished (or even partway through), run:

python3 4_reformat.py

This creates a separate xero_backup_organised/ folder with:

  • files/invoices/ — invoice PDFs named 2024-03-15_ContactName_Invoice_INV-0042.pdf
  • files/bills/ — same for bills
  • files/bank_transactions/ — receipt scans named with date, contact, and original filename
  • transactions.csv — every transaction as flat line-item rows, ready for Excel
  • summary.xlsx — four-tab workbook: Invoices, Bills, Bank Transactions, Contacts
✅ Your original xero_backup/ folder is left completely untouched. You can re-run 4_reformat.py at any time.

🔧 Troubleshooting

⌄
pip3: command not found

Try pip instead of pip3. If neither works, Python may not be installed — go back to Step 1.

can't open file '1_generate_cert.py': No such file or directory

You're not in the right folder. Use cd to navigate to where you saved the scripts first, e.g. cd ~/Desktop/xero-backup.

FileNotFoundError: cert.pem

The cert files aren't in the same folder as the scripts. Make sure you ran 1_generate_cert.py from inside the scripts folder, and that cert.pem and key.pem appear alongside the .py files.

Error: invalid_scope when logging in

The scope names Xero supports depend on when your developer app was created. The scripts use the current granular scope names (post-March 2026). If your app was created before that date, check the Configuration page in the Xero Developer portal — the available scopes are listed there and may differ.

Browser shows "can't connect to server" after Xero login

The local callback server wasn't running when the browser arrived — the script likely crashed before it started listening. Check the terminal window for errors. The most common cause is cert.pem and key.pem not being in the same folder as the scripts. Fix that, then re-run python3 2_login.py.

Script stops with "daily quota" message

Normal — Xero's 5,000 API calls/day limit has been reached. Just re-run python3 3_backup.py the following day. It will resume where it left off.

Token expired / need to log in again

If you haven't run the backup in 60+ days, the refresh token may have expired. Re-run python3 2_login.py to authenticate again. You won't lose any already-downloaded data.

Notes

  • Payroll data is not included (requires separate Xero Payroll API scopes)
  • Credit notes and purchase orders are not available as API scopes for apps created after March 2026
  • The scripts are read-only — they never write anything back to your Xero account
  • Don't commit tokens.json, tenants.json, or cert.pem to GitHub — a .gitignore is included in the repo to prevent this
